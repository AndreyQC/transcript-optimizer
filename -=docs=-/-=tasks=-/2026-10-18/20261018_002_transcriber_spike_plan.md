## 1. Цель

Проверить реализуемость и снять неизвестные до планирования Phase 10:

1. **Собираемость.** Связка `transcribe-rs` (ONNX-путь, без whisper.cpp) +
   `polyvoice` собирается `--release` на целевой машине (Windows, CPU, без GPU).
   Рецепт фич проверен AIVORelay (см. 20261018_003, находка 1).
2. **Скорость.** Wall-clock по стадиям: decode / ASR / diarization / merge.
   Экстраполяция на часовую встречу.
3. **Качество ASR на русской речи.** Parakeet v3 — основная модель пользователя;
   опциональное сравнение с GigaAM (русский-специализированная).
4. **Диаризация.** Адекватность разделения 2–4 спикеров на реальной встрече.
5. **API-границы.** Что реально выставляет `transcribe-rs` на parakeet: сегментные
   таймкоды, слово/сегмент-выравнивание; что выставляет `polyvoice`: формат входа
   (WAV-параметры), выход (спаны спикеров). `initial_prompt` на parakeet
   неприменим (обзор AIVORelay, ограничение 3) — из проверок убран; имена и
   термины правим словарём замен в пост-обработке.

Спайк — одноразовый код: `anyhow` + `eprintln`, без UI, без конфигов, пути —
аргументами CLI. Аудио декодируется в память; промежуточные JSON-стадии пишем
рядом с видео.

## 3. План работ

1. `cargo new spike/transcriber`; депы: `transcribe-rs` (`onnx`, `vad-silero`),
   `polyvoice`, `hound`, `rodio`, `rubato`, `serde_json`, `anyhow`.
2. Стадия decode: нативный декод входного файла в f32 mono 16 кГц
   (WAV → `hound`, остальное → `rodio`), с замером времени.
3. Стадия ASR: parakeet-v3 на декодированном аудио, вывод сегментов
   с таймкодами в JSON.
4. Стадия диаризации: polyvoice на том же аудио → спаны спикеров.
5. Сшивка: сегменты × спаны → финальный `transcript.txt`.
6. Свод метрик в `metrics.json`: время по стадиям, длина аудио, пик RAM
   (по данным Диспетчера задач — грубо), версия модели.

## 4. Входные данные (нужно от пользователя)

- **Sample-видео (или аудио) с русской речью, 2–4 спикера, 5–15 минут** — блокер:
  без него спайк не запускается. Путь передаётся аргументом, файл не коммитится.
- Опционально: длинная запись (~час) для экстраполяции времени.
- Внешние зависимости НЕ требуются: ffmpeg не нужен (нативный декод),
  whisper.cpp-toolchain не нужен (ONNX-путь). Модель parakeet-v3 int8
  скачивается при первом запуске (~0.5–1 ГБ).

## 5. Проверки (критерии успеха)

- [ ] `cargo build --release` в `spike/transcriber/` — exit 0 на целевой машине.
- [ ] Полный цикл на sample-файле проходит без падения; `transcript.txt` и
      `metrics.json` на выходе.
- [ ] Таблица замеров: стадии × время (parakeet-v3; опционально GigaAM),
      экстраполяция на час.
- [ ] Качество ASR оценено вручную: имена/термины, читаемость русской речи.
- [ ] Диаризация оценена вручную: % сегментов с правильным спикером
      (субъективно, по прослушиванию контрольных точек).
- [ ] API-границы зафиксированы письменно: что доступно, чего не хватает.

Go/no-go для Phase 10: собирается + час встречи укладывается в приемлемое время
(ориентир: < 1 часа wall-clock) + ASR читаем на русской речи.

## 6. Риски

- **Скачивание моделей при первом запуске** (~0.5–1 ГБ) — обработать офлайн
  внятной ошибкой; источник — tarball `blob.handy.computer` (по образцу AIVORelay)
  или HuggingFace.
- **polyvoice требует свои параметры аудио** — свериться с docs.rs до написания
  кода стадии 4; конфликт параметров решается на стадии decode.
- **Память** — parakeet 0.6b в int8 ~1 ГБ + диаризация ~100 МБ: запас под 32 ГБ
  большой, но замерить.
- **polyvoice 1.0.0 — версии считанные дни** (вышла 2026-10-01) — возможны
  шероховатости API; при проблемах рассмотреть `speakrs` (DER 7.1%).
- Снимаемый риск: собираемость transcribe-rs на Windows доказана AIVORelay
  (тот же рецепт фич); whisper.cpp-toolchain более не требуется.
