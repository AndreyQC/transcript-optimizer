## 1. Цель

Проверить реализуемость и снять неизвестные до планирования Phase 10:

1. **Собираемость.** Связка `transcribe-rs` + `polyvoice` собирается `--release`
   на целевой машине (Windows, CPU, без GPU), включая whisper.cpp-toolchain
   (cmake/clang через `whisper-rs`).
2. **Скорость.** Wall-clock по стадиям: ffmpeg-extract / ASR / diarization / merge.
   Экстраполяция на часовую встречу.
3. **Качество ASR на русской речи.** С `initial_prompt` и без — разница заметна
   на именах/терминах?
4. **Диаризация.** Адекватность разделения 2–4 спикеров на реальной встрече.
5. **API-границы.** Что реально выставляет `transcribe-rs`: проброс
   `initial_prompt`, сегментные таймкоды, слово/сегмент-выравнивание; что
   выставляет `polyvoice`: формат входа (WAV-параметры), выход (спаны спикеров).

Спайк — одноразовый код: `anyhow` + `eprintln`, без UI, без конфигов, пути —
аргументами CLI. Промежуточные артефакты (WAV, JSON-стадии) пишем рядом с видео.

## 2. Решения (зафиксировано заранее)

| Параметр | Решение |
|---|---|
| Место кода | `spike/transcriber/` — standalone-крейт, НЕ член workspace `app/src-tauri` (ML-депы не попадают в сборку приложения) |
| Судьба кода | Одноразовый; в Phase 10 наработки переносятся в постоянный sidecar-крейт `pipeline/` |
| ASR | `transcribe-rs = "0.3"` (решение Q2) |
| Диаризация | `polyvoice = "1.0"` (решение из final §2) |
| Аудио | ffmpeg через `std::process::Command`: 16 кГц, mono, 16-bit WAV |
| Модели ASR | Два прогона: Whisper `small` (~466 МБ, базовый замер скорости) и `medium` (качество; если small неприемлемо медленно — наоборот) |
| initial_prompt | Строка-аргумент CLI; подаём в transcribe-rs, если API позволяет; если нет — фиксируем как ограничение и проверяем только качество без него |
| Сшивка | Упрощённая: сегменту ASR — спикер с максимальным пересечением таймкодов; тай-брейк — больший спан. Без ручной настройки |
| Выход | `transcript.txt` в формате `[HH:MM:SS] Speaker N: текст` + `metrics.json` (стадия → секунды) |

## 3. План работ

1. `cargo new spike/transcriber`; депы: `transcribe-rs`, `polyvoice`, `serde_json`,
   `anyhow`.
2. Стадия extract: `ffmpeg -i <video> -ac 1 -ar 16000 -sample_fmt s16 out.wav`
   c замером времени.
3. Стадия ASR: транскрибация WAV, вывод сегментов с таймкодами в JSON.
   Отдельный прогон с `initial_prompt` (если доступен).
4. Стадия диаризации: polyvoice на том же WAV → спаны спикеров.
5. Сшивка: сегменты × спаны → финальный `transcript.txt`.
6. Свод метрик в `metrics.json`: время по стадиям, длина аудио, пик RAM
   (по данным Диспетчера задач — грубо), версия модели.

## 4. Входные данные (нужно от пользователя)

- **Sample-видео с русской речью, 2–4 спикера, 5–15 минут** — блокер: без него
  спайк не запускается. Путь передаётся аргументом, файл не коммитится.
- Опционально: длинное видео (~час) для экстраполяции времени.
- На машине нужен `ffmpeg` в PATH и toolchain для whisper.cpp (MSVC Build Tools +
  cmake; при отсутствии — установить, это тоже часть проверки собираемости).

## 5. Проверки (критерии успеха)

- [ ] `cargo build --release` в `spike/transcriber/` — exit 0 на целевой машине.
- [ ] Полный цикл на sample-видео проходит без падения; `transcript.txt` и
      `metrics.json` на выходе.
- [ ] Таблица замеров: стадии × время (small и medium), экстраполяция на час.
- [ ] Качество ASR оценено вручную: имена/термины, сравнение с/без `initial_prompt`.
- [ ] Диаризация оценена вручную: % сегментов с правильным спикером
      (субъективно, по прослушиванию контрольных точек).
- [ ] API-границы зафиксированы письменно: что доступно, чего не хватает.

Go/no-go для Phase 10: собирается + час встречи укладывается в приемлемое время
(ориентир: < 1 часа wall-clock на medium) + ASR читаем на русской речи.

## 6. Риски

- **whisper.cpp-toolchain на Windows** — главный риск собираемости; если упрётся,
  попробовать feature-флаги transcribe-rs на ONNX-движок или модели Moonshine
  (multi-engine — запасной путь из Q2).
- **Нет `initial_prompt` в API transcribe-rs** — спайк продолжает без него;
  пункт уходит в риски Phase 10 (патч или upstream-PR).
- **polyvoice требует свои параметры аудио** — свериться с docs.rs до написания
  кода стадии 4; конфликт параметров решается на стадии extract.
- **Память 32 ГБ** — medium в int8 ~2–3 ГБ + диаризация ~100 МБ: запас есть,
  но замерить.
