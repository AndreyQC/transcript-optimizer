## 1. Что сделано

Standalone-крейт `spike/transcriber` (~460 строк `main.rs`), полный цикл
`decode → ASR → diarization → merge` на реальной встрече:

- **decode**: webm/opus (563 МБ, 19.2 мин, 2 ch 48 кГц) → f32 mono 16 кГц
  за ~3 с. Демукс — symphonia (mkv), декод Opus — `audiopus` (libopus
  собирается из исходников через cc), миксдаун + ресемплинг — rubato.
  ffmpeg не используется.
- **ASR**: `transcribe-rs` 0.3.12, `ParakeetModel` int8, чанки по 120 с,
  `TimestampGranularity::Segment`, склейка через `offset_timestamps`.
- **diarization**: `polyvoice` 1.0.0, `pipeline-native` + `vbx`,
  `Profile::Balanced`, кластеризатор VBx.
- **merge**: сегменту ASR — спикер с максимальным пересечением таймкодов;
  выход `[HH:MM:SS] Спикер N: текст`, метрики — `metrics.json`.
- Модели ASR — переиспользованы из установленного AivoRelay
  (`%LOCALAPPDATA%\Packages\MaxITService.AivoRelay_.../.../models`),
  раскладка файлов совпала с ожиданиями transcribe-rs; скачивать не пришлось.

## 2. Замеры (Windows, CPU, без GPU)

Sample: `2026-10-16_124052_LM.HRDO-2.DEV.sync.webm` — 19.2 мин, русская речь,
2+ спикера, дальний/фоновый звук.

| Прогон | decode | ASR | диаризация | всего | RTF ASR | RTF диар |
|---|---|---|---|---|---|---|
| parakeet-v3 int8, полный (1152 c) | 3.0 с | 142.7 с | 10.2 с | **156 с** | **0.124** | 0.009 |
| parakeet-v3 int8, 600 с | 2.9 с | 69.7 с | 4.9 с | 78 с | 0.116 | 0.008 |
| GigaAM v3 int8, 600 с | 2.9 с | 46.6 с | 4.7 с | 54 с | 0.078 | 0.008 |

Экстраполяция на часовую встречу: ~7.5 мин ASR + ~55 с диаризации ≈
**9 мин на час материала** — критерий плана «< 1 часа wall-clock» превышен
с запасом на порядок.

## 3. Качество (ручная оценка)

- **Parakeet v3 на русской речи — рабочий.** Транскрипт читаем, пунктуация
  есть, имена («Настя», «Мишка») и термины («токены», «сессия», «хайринг»)
  узнаются. Характерные ошибки на дальнем звуке: «четики» (чеки?),
  «мини-масс» (мини-макс?), непоследовательный «хайринг/хайнг» — это именно
  то, что чистится словарём замен transcript-optimizer.
- **GigaAM v3 (ru-специализированный) на этом материале хуже**: слипшиеся
  слова («ереходим», «Мминимакиже»), пропуски. Быстрее (RTF 0.078), но по
  качеству на дальнем звуке parakeet выигрывает.
- **Диаризация**: полный файл → 3 спикера, 172 turns, смена спикеров в
  транскрипте правдоподобна (Спикер 0 ведёт, 1 — короткие реплики,
  2 — похоже, дальний/шумовой кластер). Формальная проверка на слух
  (процент корректных атрибуций) не проводилась — осталось за рамками.
- **На 10-минутном отрезке VBx выродился в 1 спикера** (60 turns). На полном
  файле — норм. Вывод: короткие окна VBx-кластеризации нестабильны; ручки
  тюнинга есть (`embed_window_secs`, `ClustererKind::Ahc{threshold}`,
  `max_speakers`), эксперименты — в Phase 10.

## 4. Находки спайка (влияют на Phase 10)

1. **transcribe-rs 0.3.12 не собирается с ort rc.14** — крейт объявляет
   `ort "2.0.0-rc.12"` диапазоном, а между RC у ort сломан
   `Session::builder`. Лечится пином `ort = "=2.0.0-rc.12"` у себя.
2. **symphonia не декодирует Opus** (0x1005) — известный пробел 0.5.x.
   Решение: symphonia как ДЕМУКСЕР mkv/webm + `audiopus` (libopus из
   исходников, без системных зависимостей). AivoRelay, судя по всему,
   webm+opus фактически не декодирует.
3. **«en-only» у parakeet в transcribe-rs — устаревшие метаданные**:
   CAPABILITIES говорят `languages: ["en"]`, но модель v3 int8 из модели
   AivoRelay грузится и отлично транскрибирует русский (словарь из vocab.txt
   модели).
4. **Корпоративный TLS-прокси роняет auto-download polyvoice** (ureq:
   `invalid peer certificate`). Модели скачаны curl'ом в
   `%LOCALAPPDATA%\polyvoice\models` (9 файлов, ~11 МБ), SHA-256 сверен
   вручную; крейт дополнительно проверяет по своему манифесту. Для Phase 10:
   прокинуть системный cert-store или качать системным curl.
5. **GigaAM — CTC без таймкодов** (`supports_timestamps: false`) → для
   сшивки с диаризацией не годится, только текстовое сравнение.
6. `max_audio_samples` у polyvoice по умолчанию = 1 час 16 кГц — больше
   нужно поднимать явно (для длинных вебинаров).
